### P4 first attempt: no board device tree (2026-10-31)

The first `--resume` stopped in P4's `sudo cfw update-environment` with
`Foldable product identity needs the board's own device tree.` (log kept as
`P4-update-failed-no-board-tree.log`).

- Cause: `duo-display-matrix` is a clone of the imported copy, and an export
  without the IPSW leaves out `FirmwareOriginals` by design
  (`VPhoneBundleTransfer.swift`, the `includeIPSW` exclude). Recovery found
  no iPhone19,4 27.1 (24A94425) IPSW in `~/.vphone/ipsws` or
  `.build/acceptance/ipsws`. The same run had already printed that the board
  audio repair was skipped for the same reason.
- No guest damage: the installer patches an APFS clone of `Disk.img` and
  renames it over the original only on success. `Disk.img` kept its P3 stop
  mtime (15:46) and `PatchReceipt.plist` is unchanged (Oct 30 15:29).
- Finding (not fixed, so the pinned candidate binaries stay unchanged): the
  foldable product-id/displays check runs in `patchPreboot`, after every
  system-volume patch has been computed (~8,700 log lines). The HomePod donor
  checks run before any disk work. For the foldable case the precondition
  should move to the same early place. (2026-10-31: moved; see the
  follow-up below.) An imported Duo machine without its
  IPSW cannot run `cfw update-environment` with the standard selection until
  the tree is restored.
- Fix for this run: copied `DeviceTree.v68ap.im4p` (sha256 `68d93514…`,
  identical in seed, candidate and baseline) from the seed into
  `duo-display-matrix/FirmwareOriginals/iPhone19,4_27.1_24A94425_Restore/Firmware/all_flash/`,
  which is the path the tool names. P4 is rerun with `--resume`.

enables `preboot-cfw-devicetree_foldable_product_id` or `_displays` without a
staged board tree right after the HomePod donor checks, before the
