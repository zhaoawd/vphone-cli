## 2. 本地 CLI 行为（事实，源码）

| 命令 | 参数 | 锁与拒绝 | 与 Launchpad 相关的行为 |
| --- | --- | --- | --- |
| `vm config <name>` | `--cpu`、`--memory`（MB）、`--network nat\|bridged\|none`、`--bridge-interface` | `withBundleLock(operation: config)` | `hostOnly` 被拒绝 |
| `vm rename <name> <new>` | — | 源 bundle 锁 + 库根锁 | 新名称规则：非空、无 `/`、不以 `.` 开头 |
| `vm clone <name> <new>` | — | 源 bundle 锁贯穿复制与发布 | 保留设备身份（NVRAM、机器标识、SEP 存储） |
| `vm delete <name>` | `--force` | bundle 锁 | 无 `--force` 时从 stdin 读确认；Launchpad 子进程 stdin 为 `/dev/null`，会输出 `aborted` 并以 0 退出 |
| `vm export <name> --out <path>` | `--max`、`--include-ipsw` | bundle 锁，在任何输出之前取得 | `--out` 为已有目录时写入 `<dir>/<name>.<ext>`；生产者 tar 与压缩 tar 两段管道，输出文件由压缩 tar 写入；`VPhoneProgressBar` 只在 stderr 为 TTY 时输出 |
| `vm import <archive>` | `--name` | 解包到私有 staging，库根锁内发布 | 默认使用归档内顶层名称 |

持锁被拒绝时 CLI 输出（本批真实运行记录）：`Error: VM 'm' is busy: it is held by pid 60917 running operation "boot" (instance CD1E5EAB-…); stop the VM first`，退出码非 0。

## 5. 实现要点（事实）

### 5.1 命令

| 动作 | 参数 |
| --- | --- |
| 设置 | `vm config <name> --library-root <root> [--cpu N] [--memory MB] [--network nat\|bridged\|none [--bridge-interface IF]]`；只传改动的字段；多台机器逐台运行 |
| 改名 | `vm rename <name> <new> --library-root <root>`；成功后选中新名称 |
| 克隆 | `vm clone <name> <new> --library-root <root>`；成功后选中克隆 |
| 删除 | `vm delete <name> --force --library-root <root>`；多台逐台运行 |
| 导出 | `vm export <name> --out <file> --library-root <root> [--max] [--include-ipsw]`；多台按队列逐台运行 |
| 导入 | `vm import <archive> --library-root <默认库根>` |

- 全部经 `VPhoneLaunchpadCommandLine.run(_:)`（管道模式），记录到命令历史；周期 `vm list` 不记录（B1 起）。
- 取消导出：`cancelExport` 取消导出任务，`withTaskCancellationHandler` 只向本次 `vm export` 子进程发 SIGINT（B1 `interrupt()`，未改）。排队中的导出直接移出队列，不运行命令。
- 删除：Launchpad 源码中唯一的文件删除是 `VPhoneLaunchpadExportOutput.removeCancelled` 中的 `unlink`；机器目录只由 `vm delete` 删除。

### 5.2 界面

- 操作菜单（工具栏 “…” 与表格右键）：Cancel Export（有导出时）、Start、Start Headless、Stop、Settings…、Rename…（单台）、Clone…（单台）、Export…、Open Console、Show Console Log in Finder（单台）、Show in Finder、Delete…。Settings、Export、Delete 支持多选，要求每台都满足 `canEdit`。
- 设置 sheet：CPU 步进 1…宿主核心数，内存 2048…65536 步长 1024，网络 NAT/Bridged/None，Bridged 时可填接口；`hostOnly` 显示为 None（上游相同）。
- 导出 sheet：单台为 “Maximum compression”“Include the restore IPSW directory” 与 `NSSavePanel`；多台为 `NSOpenPanel` 选择文件夹。
- 设计系统：所有 sheet 背景 `#1A1A1A`、等宽字体、1px `#333333` 分隔线；删除 sheet 的路径框为 1px 边框面板；无自定义阴影。

### 6.1 取消导出测试与 SIGINT

- 事实：替身 `vm export` 为 `/bin/sh` 脚本，循环中前台运行 `sleep 0.1`。首次未设 trap 时，SIGINT 送达后脚本继续运行到结束（状态 0）。推断：macOS `/bin/sh`（bash）在等待前台子进程期间收到 SIGINT，而子进程不是因 SIGINT 结束时，继续执行脚本。替身改为 `trap '…; exit 130' INT` 后，测试断言状态为 130。
- 事实：试验性地把管道模式从 `Process` 改为 `posix_spawn` 并去掉 `POSIX_SPAWN_SETSIGDEF` 后，在全量 `VPhoneLaunchpadKitTests` 中本批取消导出测试失败（状态不是 130），B1 的 `cancellingARunInterruptsOnlyItsChild` 与 B2 的分离启动测试也失败或超时（`negative-no-sigdef-full.log`；单独过滤运行时通过，`negative-no-sigdef.log`）。该试验改动已撤销，`VPhoneLaunchpadChildProcess.swift` 与 `539773c` 相同。推断：全量运行时测试宿主进程忽略 SIGINT，`Process` 启动的子进程不继承该忽略状态；本批取消导出测试在 SIGINT 未送达时失败。
- 该试验运行超时后，向本次测试启动的 8 个替身子进程（`launchpad-detached-*`、`launchpad-launch-*` 脚本）发送 SIGKILL 结束它们；未向其他进程发信号。

## 8. 事实、推断与未覆盖

事实：

- Launchpad 只经内嵌 `vphone-cli` 的 6 个编辑命令修改机器；命令值只能由工厂构造；源码扫描与单元测试同时检查。
- 运行中（锁被持有）的机器：Launchpad 不取锁、不探测锁，按 stopped 提供编辑；CLI 拒绝，拒绝原文出现在 `actionError` 详情中（真实 CLI，第 6.2 节）。
- 取消导出只删除本次导出创建的普通文件；真实 `vm export` 取消后输出文件不再出现（第 6.2 节）。
- 删除只经 `vm delete --force`，前有显示完整路径的确认 sheet（截图）。

推断：

- 取消导出时压缩 tar 可能在 `vm export` 结束后短暂继续写入已被 `unlink` 的文件；路径不会重新出现。依据：tar 在开始时打开输出文件；真实测试中 3 秒后路径不存在。若取消发生在压缩 tar 打开输出文件之前，存在 tar 随后创建文件的可能，未构造该时序验证。
- `/bin/sh` 等待前台子进程时对 SIGINT 的处理导致第 6.1 节首次结果；未查阅 bash 源码确认。

未覆盖：
