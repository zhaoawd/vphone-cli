# E4：客户机传输故障与取消验证

日期：2026-09-12。实现基线：`02f9b35`。E4 代码、协议集成测试和远端 CI 已完成；实际 VM 重连补充实验在同日后续排查中通过，历史失败和后续结果分别记录。本项沿用 vphone-control v1，修改宿主传输与客户机协议源代码，不应用二进制补丁。C4 继续暂停。

## 问题、证据与修复

| 问题 | 失败证据 | 修复与原因 |
| --- | --- | --- |
| 4 MiB 边界不同 | 客户机接收允许恰好 4 MiB；宿主使用严格小于，4 MiB 响应导致断线 | 两端接收与发送均限制为 1–4194304 字节 JSON；长度前缀不计入该范围 |
| 未知或重复 ID 的附带数据未消费 | 未知 file_data 后紧跟正常响应，原实现将原始数据当作下一帧头并断线 | 先解析并消费完整文件/图片数据，再查找待处理 ID；未知、重复、取消后或超时后的数据也按相同规则消费 |
| 文件读取期间超时失效 | 原实现收到文件头后立即移除待处理请求，随后阻塞读取 | 完整响应到达后才移除请求；超时、取消、断线和正常响应通过同一加锁移除操作竞争，只交付一次结果 |
| Task 取消没有结束等待 | 取消 downloadFile 后仍等到请求超时 | 普通请求、文件上传和剪贴板上传共用 performRequest；取消及时恢复 continuation，尚未开始写入的请求被跳过 |
| 部分数据长期占用读线程 | 客户机发送文件头和少量数据后停发，请求已超时而连接仍保留 | poll 与非阻塞 recv 使用单调时钟绝对期限；短读与 EINTR 重试不重置期限，失败后关闭当前连接 |
| 旧连接回调可能影响新连接 | 代码检查发现部分写失败、更新完成及 heartbeat 回调无连接身份校验 | 回调核对 attempt token 和描述符；epoch 丢弃旧写队列，新测试验证阻塞上传与积压请求不能进入替换连接 |
| 描述符生命周期不覆盖后台任务 | 原实现仅传裸 fd，释放连接与后台读写可能并行 | 每次连接持有独立 dup；所有读写任务保留该持有者，shutdown 解除阻塞，最后一个任务释放后才 close，避免 fd 被提前复用 |
| 客户机系统调用中断被当作断线 | 对实际 Objective-C 实现注入 EINTR，原始 socketpair 测试失败 | vp_read_fully 和 vp_write_fully 在 EINTR 后重试，保留短读写循环 |
| 客户机发送端没有帧上限 | 原代码可以发送超过接收上限的 JSON | 序列化后检查 VP_MAX_MESSAGE_SIZE；超限时返回 NO，不发送帧 |

新增的 VPhoneControlChannel 负责连接描述符所有权。VZ 连接与 socketpair 使用相同握手、解析、请求及写队列代码。测试可以注入短期限；正式 CLI 没有新增期限参数。AppDelegate 退出时显式关闭客户机控制通道并取消自动重连。

## 协议与期限

| 对象 | 当前规则 | 兼容性影响 |
| --- | --- | --- |
| JSON 帧 | uint32 大端长度；1–4 MiB；顶层为对象 | 两端统一包含 4 MiB 上限；宿主还要求 v 为数值 1、t 为字符串 |
| 响应 ID | 宿主生成十六进制字符串；响应按 ID 匹配，不按到达顺序 | 并发响应可以乱序；重复或未知 ID 不交付给其他请求 |
| 原始响应数据 | file_data.size 或 clipboard_get.image_size 为非负整数，最大 64 MiB | 新增接收上限；负数、小数、布尔值、字符串、缺失或超限大小使连接结束；较大文件需要后续分块协议 |
| 握手 | 默认 8 秒 | 原默认值保持不变 |
| 帧读取 | 从等待帧头开始，帧头和 JSON 共用 180 秒绝对期限 | 不因短读或每次收到字节而重新计时 |
| 原始数据读取 | 头部解析后最多 180 秒 | 客户机停发或只持续发送少量数据时仍有上限 |
| 排队与写入 | 每项从入队开始最多 180 秒，含 JSON 与其原始数据 | 现在覆盖普通请求与无响应回调命令；到期 shutdown 当前连接，解除阻塞写入 |
| 响应等待 | 写入完成后启动原有 10/30/180 秒期限 | 请求排队、写入和响应等待分别计时；不是统一的端到端 180 秒 |

文件头与数据仍在同一个串行写任务中发送。客户机通过同一 writer mutex 发送响应头与原始数据，避免并发工作线程交错字节。宿主控制 UDS 的 E1/E2 限制属于另一个协议层，不与这里的 vphone-control 长度限制合并解释。

## 取消的含义

- Task 在提交前已取消：不发送请求，抛出 CancellationError。
- 请求仍在队列中：从待处理表移除并恢复调用方；写任务执行前检查请求是否仍存在，已取消则跳过。
- 写入已经开始：取消宿主等待；已经开始的完整帧及数据继续在写期限内发送，避免截断一帧后继续复用同一字节流。
- 请求已到客户机：本协议没有客户机取消指令。shell、文件修改、应用操作可能继续；取消与超时错误文本明确附带 `guest operation may continue`。
- 迟到响应：完整消费其数据后丢弃，不再次恢复已结束请求。连接关闭或读取失败也不能证明客户机操作已经停止。

上述等待处理与客户机自身的 shell 执行期限分别解释。本项没有新增客户机进程终止或文件回滚协议。旧连接响应只在连接身份仍匹配时交付。

## 自动化验证

新增 13 个 Swift 集成测试使用真实 socketpair，通过 VPhoneControl 的异步接口验证握手、大小端与边界、乱序 ID、文件及剪贴板数据、未知/重复 ID、取消及迟到结果、读取期限、写入阻塞、断线和替换连接。使用分片写入检验短读取；阻塞的大上传检验部分写入及写看门狗。重复完成 continuation 会触发测试进程错误，取消/超时/EOF/迟到响应路径均完成且未发生重复交付。

新增 4 个 Python 测试编译实际 vphoned_protocol.m，在 macOS Foundation 上使用真实 stream socket 和注入的短读写/EINTR。覆盖恰好 4 MiB、超限拒绝、零长度/非法长度，以及 12 个并发文件响应的 ID 与原始数据一致性。该测试不启动完整 iOS 守护进程。

完整 `make test` 通过：85 个 Python；127 个 XCTest（3 个跳过，0 个失败）；331 个 Swift Testing、53 个 suite。相关控制和定位回归通过。客户机完整源码通过 iOS arm64 交叉编译，产物为独立 `/tmp/vphoned-e4`，未覆盖现有守护进程文件。

`make build BUNDLE=.build/vphone-e4.app` 完成 release 编译、entitlements 签名及独立 app bundle。保留无请求回调日志后，最终 13 个传输专项测试再次通过。

## 实际运行

现有空闲 `vm-2607-rig2`（iOS/cloudOS 26.1，23B85，exp）使用独立 E4 app bundle 引导。传入不存在的 vphoned 路径，关闭本轮客户机自动更新；因此该实验验证新宿主与现有客户机的兼容性，修改后的客户机协议另由原始代码测试及 iOS 交叉编译验证。

headless 能力查询、Shell、18 字节含 NUL/0xff 文件往返、应用列表（236 项）、legacy 定位设置/停止和无画面截图拒绝均通过；退出码 0，socket 已删除。客户机未声明 location_owned，本轮不作为 E5 所有权与持久化验收。

第一次重连复验在故障注入前达到 120 秒启动预算；vsock 建连持续返回 Connection reset by peer，没有进入协议握手。测试退出码为 0，socket 已清理；脚本因未完成连接检查返回失败。原因未查明，原记录保留在 reconnect 目录。300 秒复验中，宿主 socket 在 1.008 秒可用，但直到预算结束仍未连上客户机；日志同样为 vsock 建连失败，没有进入协议握手。两次实验均未执行守护进程终止，不能声称本轮实际 VM 自动重连通过。两次都在优雅停止期限后使用 VZ 停止，进程以 0 退出，socket 已删除。未据此确定启动失败原因，也未修改固件或宿主安全设置。

终态核对：原 vm-2607 仍以 PID 57388 运行；原应用二进制的 inode、mtime、大小未变；本轮三个测试进程均不存在，rig2 的 socket 不存在。可用磁盘约 14.58 GiB；该数值是终态测量，不据此归因磁盘变化。

E4 清单的验收对象是客户机协议集成测试。断线、替换连接、旧写队列及迟到响应已在真实 socketpair 上通过；实际 headless 功能也通过一次。补充实机重连失败保留为运行限制，不能替代或扩展为 F2 的完整双 VM 验收。推进 E5 前需要调查 rig2 的普通引导与守护进程就绪状态。本地日志、红绿测试证据、运行脚本及 SHA-256 清单保存到 `research/artifacts/e4-transport-2026-09-12/`。
