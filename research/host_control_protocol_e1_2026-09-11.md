# E1：宿主机控制协议约束

日期：2026-09-11。范围：`VPhoneHostControl` 的 Unix domain socket；不修改客户机 vsock 协议。

## 消息与容量

每个连接接收一个 UTF-8 JSON 对象，`t` 必须为字符串。首个 LF 终止请求；LF 后的数据被忽略。EOF 也可终止非空请求，空 EOF 直接关闭连接。CRLF 的 CR 作为 JSON 尾随空白处理。UTF-8 解码在完整消息接收后执行，允许一个字符跨多次 `read()`。

| 对象 | 限制 | 原因 |
| --- | --- | --- |
| JSON 请求 | 2 MiB 原始字节，不包含终止 LF | 旧逻辑按累计 4096 字节决定是否继续读取，实际接受长度依赖分片；新限制按消息累计字节判断 |
| `file_put.data_b64` | 解码后最多 1 MiB | 在请求上限内预留 Base64 和 JSON 字段空间 |
| `file_put.load` | 最多 64 MiB，只读取普通文件 | 避免无界内存分配；拒绝 FIFO 和设备文件，避免等待流式输入 |

两种文件字段同时存在时保留原有 `data_b64` 优先行为。宿主机文件大小既在打开后通过 `fstat` 检查，也在读取过程中检查，防止文件增长绕过限制。限制是本版本的接口选择，不代表客户机存储容量或可用内存。

错误响应保留 `ok:false`、`error`，新增稳定 `code`：`request_too_large`、`read_timeout`、`invalid_json`、`file_too_large`、`io_error`。既有命令参数错误仍保留原响应格式。响应为 JSON + LF；连接随后关闭。客户端必须接收完整响应行才能认定响应有效。

## 连接与权限

socket 路径仍为 VM 配置文件所在目录下的 `vphone.sock`，路径必须能放入系统 `sockaddr_un.sun_path`。目录必须归当前有效 UID 所有，且不能允许组或其他用户写入；目录本身不能是符号链接。推荐目录权限 0700，0755 也符合检查。程序不修改现有目录权限。

socket 权限设为 0600。接收连接后使用 `getpeereid` 检查对端有效 UID，只有同一用户可进入命令处理。现有路径只有在属于当前用户且类型为 socket 时才可替换。同用户进程属于信任边界：命令允许读取宿主机文件和控制客户机，不提供按命令授权。

读请求和写响应分别使用 5 秒单调时钟期限。读取期限从工作线程开始读取计算，不因新增字节而重置；写入期限从响应开始写入计算。socket 为非阻塞模式，`poll` 等待受剩余期限约束。写超时或对端断开时停止写入并关闭连接，不能保证客户端收到错误响应。

最多 16 个连接进入工作队列，计数覆盖请求读取、命令执行和响应写入。超过上限的连接立即关闭，不创建工作项或等待任务；监听 backlog 设为 16，由内核管理。读超时连接最多再用 5 秒尝试写出错误。禁用 socket 的 SIGPIPE，避免对端关闭导致整个宿主进程退出。

上述期限不替代命令执行期限。客户机命令继续使用 `VPhoneControl` 的既有超时；截图等回调仍无统一取消接口。若命令回调不返回，该连接会继续占用一个名额；连接上限防止工作项无限增长，但不能保证该命令完成。统一命令生命周期属于 E2 后续拆分时需要处理的限制。
