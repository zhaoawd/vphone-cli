## 占用与环境

持有 vm-2607、vphone-0、127.0.0.1:27042、6378C23C514E44CC 和 vm-2607-rig2 的任务锁。暂时 SIGSTOP 主实例健康监测 PID 39330 和 agent PID 61114；不停止主宿主或共享控制服务。两个实例初始定位状态文件均不存在，主实例状态为 off。

第一轮 rig2 宿主立即退出 -9，独立帮助命令也退出 137；静态签名校验通过，此前 amfidont 进程已不存在。第一轮自动化暂停已撤销，尚未修改主客户机。随后用现有项目脚本，仅为 `.build/offline-next/source` 目录临时启动 amfidont PID 47369；帮助命令通过后重跑。未修改 SIP 或持久系统设置。

主客户机原本不声明 `location_owned`。备份客户机缓存和宿主自动更新缓存后，通过已核对 UDID 的 SSH 转发在客户机内原子替换缓存，并重启客户机守护进程。主 VM 进程保持运行。rig2 在第一次启动时备份原客户机缓存，随后启用新版客户机。两端均须声明 `location_owned` 才开始定位场景。

## 结果

| 场景 | 结果 |
| --- | --- |
| 不同 owner、坐标和 generation | 主实例 31.2/121.5、rig2 35.6/139.7；分别为 running，两个 generation 不同 |
| 持久文件与跨实例请求 | 文件摘要不同；向任一实例提交另一实例的 generation 停止请求，均返回 `location_generation_conflict`，两文件摘要不变 |
| 主实例切换流、暂停、停止 | 仅主实例持久文件被清除；rig2 坐标、owner、generation 和持久文件保持不变 |
| 只重启 rig2 | 主实例 generation、坐标及持久文件摘要不变，交付序列继续递增；rig2 恢复自己的固定位置并生成新 generation，旧 generation 被拒绝 |
| 停止 rig2 定位源 | 主实例继续保持自己的源和坐标 |

结合此前单实例重启、流不恢复、损坏文件及历史重连/GUI 切换证据，E5 清单范围完成。整体完成计数为 17/28；F2 不关闭。

## 恢复结果

两端原客户机缓存均经文件接口逐字节恢复；两个宿主缓存和配置与备份一致。两实例定位持久文件均不存在；主实例状态恢复 off，原客户机能力已恢复。rig2 已关闭并移除 socket；主实例仍为原 PID 33731，未重启。

所有任务锁已释放，健康监测和 agent 原 PID 均恢复运行，健康文件更新时间晚于恢复时间，UDS 与 vsock 均为 healthy、last_error 为 null。本轮暂停到恢复约 151 秒。临时 amfidont PID 47369 已退出；agent PID 61114 对控制服务 127.0.0.1:8100 的两个 TCP 连接均为 ESTABLISHED。

本轮没有改写共享默认宿主程序，也没有修改固件、内核或恢复镜像。
