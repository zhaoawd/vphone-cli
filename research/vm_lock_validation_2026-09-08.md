# B2 VM 排他锁与运行记录

日期：2026-09-08。前置提交：A1 `b7d0382`、A2 `2ac6c51`、B1 `32d1a5f`。

## 锁协议

Swift 的 `VPhoneVMLock` 和 Python 的 `scripts/vm_lock.py` 对 VM 目录的文件描述符执行非阻塞排他 `flock`。本机已验证 macOS 支持目录锁。目录的设备号和 inode 构成 bundle 标识；符号链接和 `/var`、`/private/var` 路径别名指向同一锁对象。不同 VM 目录互不阻塞。

没有可删除的独立锁文件。删除运行记录不会释放锁，过期记录也不会阻止取得锁。锁由内核随最后一个持有描述符关闭而释放。

两种生命周期明确区分：

- Swift 启动进程持有 `VPhoneVMLock` 对象，描述符设置 `O_CLOEXEC`。正常返回时显式 `LOCK_UN` 后关闭描述符；异常进程退出由内核回收。普通子进程不在 exec 后继承。调用侧使用属性或 `withExtendedLifetime` 防止编译器提前结束对象生命周期。
- Shell 离线操作由 Python 取得锁后 `exec` 执行，因此记录 PID 与 Shell 主进程一致。描述符显式设为可继承，整个操作进程树共享该锁。Shell 被终止但子进程仍在执行时，锁保留到最后一个继承者退出。
- CFW 在提权后取得锁，避免 sudo 关闭描述符。驱动重新执行后以及四个变体入口均校验继承描述符的设备号、inode 和排他锁。单独设置环境变量不能绕过一个已持有的锁。

## 运行记录

`.vphone-runtime.json` 原子替换，包含 `bundleIdentifier`、`bundlePath`、`pid`、`instanceID`、`startedAt`、`operation`。启动实例使用 UUID；时间为本次操作开始时间。记录保留用于诊断，不能据其存在判断 VM 正在运行。

此记录尚未提供 B3 所需的完整操作系统进程身份校验，当前停止命令没有改为消费该记录。B3 仍须实现并验证信号目标的实例确认。

克隆后删除复制过来的记录；导出排除运行记录和临时挂载目录。

## 接入范围

| 入口 | 锁的范围 |
| --- | --- |
| 直接 `boot`、旧 Make 启动、GUI/无窗口启动 | 在读取 manifest、初始化 VM 和打开存储前获取，持有至进程退出 |
| `vm launch` | 暂存 vphoned 时单独持锁；实际 boot 子进程再次取得并持有自己的锁 |
| 创建中的 DFU、首启、启动分析、less 启动 | 共同 boot 入口持锁；DFU 子进程确认取得锁后，编排才调用恢复工具 |
| 创建中的 firmware prepare | Python 包装器锁定 Shell 操作进程树 |
| 创建中的 firmware patch、固件目录清理 | Swift 阶段锁 |
| CFW：Swift CLI、Make、主机驱动、四个变体 | 主机驱动持锁，变体必须验证继承的锁 |
| BundleOps 配置修改、删除、重命名、克隆、导出 | 核心公开操作入口持锁，冲突时拒绝执行 |

创建流程按阶段持锁。阶段交接期间其他启动若先取得锁，后续阶段拒绝继续；本次没有实现覆盖整条创建流程的锁转移协议。

## 限制与后续工作

- 没有运行实际 VM、完整固件恢复或整条创建流程。
- B4 仍需统一其他旧 Shell 备份/恢复/切换入口、独立 firmware 命令、USB DFU 恢复的授权关系，以及所有离线操作的策略和回归覆盖。此记录不将这些入口标为已完成。
- 本协议以 VM 目录 inode 为单位。不同目录的配置若指向同一个外部磁盘文件，不会自动合并为同一锁；B4 应明确共享存储的约束。
- 锁是协作式排他协议，未使用本协议的外部工具不受其约束。不得把运行记录中的 PID 直接当作安全的停止目标。
- B1 的挂载隔离继续保留；用户原有触控修改和诊断文件不纳入 B2 提交。
