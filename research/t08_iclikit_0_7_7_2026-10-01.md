`e48e6f4` 未迁入的依据：

- 上游 2.2.3 已删除 `GuestLocationSimulation.swift`（`2352726`），`location.set` 直接调用 `simulateLocation`。本地保留 2.0.8 的应用侧定位桥：daemon 写 `/var/mobile/Library/Caches/vphone-location.json`，`libvlocation.m:31-32` 读取时拒绝 `vertical_accuracy < 0`。
- daemon 若接受 -1，会返回 `simulating: true`，而应用侧读取该文件返回 nil，两端结果不一致。
- 宿主定位合约 `VPhoneSystemLocationValidation`（`VPhoneSystemLocationController.swift:29-31`）要求 `vacc > 0`，由 `SystemLocationValidationTests.swift:29` 覆盖；宿主当前不经 1339 API 发送定位（`VPhoneHostAPICommands.swift` 只映射 app/file 命令）。
- 结果：本地 `location.set` 路径上 0.7.7 的 -1 分支不可达。修改需同时改 daemon、`libvlocation.m` 与宿主校验，属于 P5 定位合约范围，本项不改。

不在 6 个提交内但属于 0.6.9→0.7.0 的上游提交 `e3c0d3f`：新增 `notify.post`/`notify.state` 端点及宿主 Controls 面板。本地未迁入该功能端点；它不是依赖升级的编译适配。

## 事实、推断与未验证

事实：

- daemon 依赖图固定为 icli 0.7.7 / `9e9a6ca9…`，解析出的 checkout 与 tag 一致；0.6.9→0.7.7 无 public 接口删除或签名变化，本地 daemon 源码无需编译适配。
- 在 macOS 主机、C locale 下，0.7.7 的 IcliKit 归档读取代码能解包 UTF-8 条目名的 IPA、读取 PAX UTF-8 路径的 deb，并跳过 `__MACOSX` 与 `._*`；0.6.9 代码在同一输入上失败。

推断（待验证假设）：

- 候选 daemon 在客户机上会通过 IcliKit 获得上述 5 项行为（服务列表、前台回退、端口释放、UTF-8 IPA、Mac 元数据）。依据是调用路径与上游 2.2.3 一致，未在客户机运行。

需真实客户机验证：

- `apps.install` 安装 UTF-8 条目名 IPA 与 Mac 打包 IPA（installd、容器注册、签名在 iOS 上的结果）。主机测试只覆盖归档读取层。
- `services.unload` 后监听端口释放（launchd 回复释放）；`services.list` 的 running/pid 字段。
- Setup Assistant 前台时 `apps.foreground` 返回 `verified: true`、`source: runningboard`；`ui.*` 前台验证。主机测试只覆盖宿主对该结果形状的映射。
- 无 altitude 定位：本地 `location.set` 按上文拒绝 -1，0.7.7 的 -1 分支不可达；宿主 `vacc > 0` 合约不变。是否改变该合约留给 P5。
