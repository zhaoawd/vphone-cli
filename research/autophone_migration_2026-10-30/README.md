## 2. 已核实的主要差异与契约细节

1. **启动与 AMFI / Core Bundle 生命周期变化。** A 的 [start_vphone.sh](../../../autophone/scripts/start_vphone.sh) 与 [amfidont.sh](../../../autophone/scripts/lib/amfidont.sh) 假定常驻 `amfidont` 守护进程（`pgrep -f "amfidont"`）、直接执行 `.build/vphone-cli.app/Contents/MacOS/vphone-cli --config` 并通过 `SIGTERM` 停止（[lifecycle.py](../../../autophone/autophone/rig/lifecycle.py)）。U 的 [host-setup.md](../../../vphone-cli-up/Documents/Guides/host-setup.md) 与 [VPhoneVirtualMachineLaunchCommand.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneCommand/VPhoneCommand/VirtualMachine/VPhoneVirtualMachineLaunchCommand.swift) 使用一次性 `vphone-escalator allow .../vphone-vm` 与 `vphone-cli host preflight`，由 `vphone-cli vm launch` 编排 `.vphoned.signed` 与 `vphone-vm` 并在 `vm stop` 发送 `SIGINT`。见 A01、U01、H08。
2. **读写门禁与 StageGuard 权限分类依赖逻辑命令名。** A 的 [uds.py](../../../autophone/autophone/device/uds.py) 仅对 `{"screenshot", "app_list", "ping", "file_get", "capabilities"}` 免除 `check_device_write`，且 [stage_guard.py](../../../autophone/autophone/device/stage_guard.py) 按顶层 `t` 映射 `OperationClass`。若在业务调用点直接把 `app_list` 或 `file_get` 改为 `t:"rpc"`，会破坏只读阶段的权限分类。见 A02、U02、U03。
3. **同名 Shell 协议冲突。** A 的 [shell.py](../../../autophone/autophone/device/shell.py) 发送单次 `{t:"shell", cmd, cwd, timeout_ms}` 并期望单行 JSON `{stdout, stderr, exit_code, timed_out, stdout_truncated, stderr_truncated}`。U 的 [VPhoneHostAutomationServer.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneVirtualization/UI/VPhoneHostAutomationServer.swift) 在进入普通命令分发前拦截 `t:"shell"` 并切换为交互终端流（`relayShell`）；`script.eval`（[GuestAPI+Script.swift](../../../vphone-cli-up/VPhoneDaemon/Daemon/GuestAPI+Script.swift)）执行 JS 脚本而非 POSIX Shell。见 A03、U02、U04、H02。
4. **应用字段映射与安装暂存清理。** A 在状态驱动中要求 `app_list` 返回 `data_container`（`/var/mobile/Containers/Data/Application/...`）；U 的 `apps.list`（[GuestAPI.swift](../../../vphone-cli-up/VPhoneDaemon/Daemon/GuestAPI.swift)）返回 `data_path`，L 在 [VPhoneHostAPICommands.swift](../../sources/vphone-cli/VPhoneHostAPICommands.swift) 做了 `data_path` → `data_container` 兼容映射。此外 U 的 `apps.install` 在 `defer` 中删除传入的 guest `path` 与 `cert_path`，调用方必须上传至临时暂存路径。见 A02、L06、U03、H03。
5. **健康三态探测与截图落盘副作用。** A 的 `probe_uds_state`（[session.py](../../../autophone/autophone/device/session.py)）通过 `app_list` 区分 `unreachable` / `host_only` / `guest_ready`。U 的 `screenshot`（[VPhoneHostAutomationServer.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneVirtualization/UI/VPhoneHostAutomationServer.swift)）在未传 `path` 时仍默认向磁盘保存全分辨率图片，且 `uds.py` 的 `GeometryGuard` 要求缩略图保持 `430x932`。见 A02、A07、U02。
6. **定位需要保留来源所有权状态机。** A 使用 `owner`、`generation`、`producer_sequence`、watchdog、`hold/stop` 和精确停止。U 已有的 `location.set/clear/current`、[VPhoneLocationProvider.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneVirtualization/UI/HostDevices/VPhoneLocationProvider.swift)、[GuestLocationdWatchdog.swift](../../../vphone-cli-up/VPhoneDaemon/Daemon/GuestLocationdWatchdog.swift) 及 [CustomFirmwareLocationdCohorting.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneCommand/FirmwarePatcher/CustomFirmware/CustomFirmwareLocationdCohorting.swift) 解决了 iOS 27 `locationd` 死锁与基础模拟，但不含多调用方租约与流序号状态机。见 A04、L02、U05、H04。
7. **相机需要保留消费回执与 QR 码合成。** A 验证 `protocol_version`、`generation`、`presentation_id`、`role` 与 `published/observed` 帧序号（[duty_via_camera.py](../../../autophone/autophone/duty/adapters/duty_via_camera.py)）。U 已有完整虚拟相机数据面、[VCamMicrophoneSource.m](../../../vphone-cli-up/VPhoneGuestComponents/VCamCaptured/Microphone/VCamMicrophoneSource.m)、[VCamProviderSource.m](../../../vphone-cli-up/VPhoneGuestComponents/VCamCaptured/Synthetic/VCamProviderSource.m) 与 [libcamfix.m](../../../vphone-cli-up/VPhoneGuestComponents/CamFix/libcamfix.m)（含预览/拍照/录像 12 类 Hook），但宿主分发器无 `camera_present/status/stop` 且 `CamFix` 未包含本地未跟踪的 [CameraMetadataOutput.inc](../../sources/VPhoneGuestComponents/CamFix/CameraMetadataOutput.inc)（`AVCaptureMetadataOutput` QR 码识别合成与 `consumed_frame_seq` 回写）。见 A05、L03、U06、H05、H06。
8. **运行身份与 Guest 辅助工具执行条件。** A 的 [runtime_observation.py](../../../autophone/autophone/device/runtime_observation.py) 在 guest Shell 中检查 `ps -o comm= -p "$PPID"` 匹配 `/*/vphoned` 且读取 `kern.bootsessionuuid`；[lock_state_helper.py](../../../autophone/autophone/device/lock_state_helper.py) 等辅助程序要求 `/var/jb/tmp` 可写可执行、`sha256sum` 可用及 `755` 权限上传。见 A03、A06、U04。

## 3. 兼容层职责划分与协议绑定原则

不把全部旧协议别名预先堆入 `vphone` 宿主层；按职责切分如下：

| 差异类型 | 建议归属位置 | 設計约束与原因 |
| --- | --- | --- |
| 命令改名、字段映射（如 `data_path`→`data_container`）、`result` 展平 | **优先在 `autophone` 统一传输适配层处理** | 保持 [stage_guard.py](../../../autophone/autophone/device/stage_guard.py) 与 [uds.py](../../../autophone/autophone/device/uds.py) 的逻辑操作名与只读/写权限分类不变，仅在底层 wire 编码/解码时映射为 U 的 `rpc` 或 `push/pull` |
| 启动、预检、进程识别（`vphone-vm`）、停止信号 | **`autophone` 生命周期适配层** | 对接 U 的 `VPhone.bundle`、`vphone-escalator`、`host preflight` 与 `vm launch/stop`，不把旧 `.build/vphone-cli.app` 目录布局迁入新仓库 |
| 定位所有权状态机、相机消费回执与 QR 码 `AVCaptureMetadataOutput` 合成 | **`vphone` 宿主及必要的 guest 扩展** | 属于 U 尚未提供的有状态设备语义与 guest Hook 行为，无法仅靠调用方字段转换实现 |
| 单次非交互 Shell（退出码、超时、截断、进程清理） | **独立设计执行契约（如候选 `shell.exec` RPC）** | 避开 U 对 `t:"shell"` 的前置交互式终端流拦截（[VPhoneHostAutomationServer.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneVirtualization/UI/VPhoneHostAutomationServer.swift)），不与终端会话混用 |

### Per-Rig 协议绑定与禁止写操作盲目重试

- **显式配置或只读协商**：每个 Rig 使用的协议模式由 Rig 配置显式指定，或在会话建立阶段仅通过无副作用的只读请求（如 `ping` / 能力查询）一次性确定并绑定。
- **严禁写操作失败后猜测协议自动重试**：对于 `tap`、`swipe`、`type`、`app_launch`、`app_terminate`、`ipa_install`、`location*`、`camera*`、`file_put`、`shell` 等写操作，一旦返回失败或未知命令，立即按契约报错返回，不得自动切换协议重发，防止重复安装、重复点击或状态污染。

### 单次 `shell.exec` 候选方案的 5 项必验边界

将独立 `shell.exec` RPC 作为候选方案（在未完成下列契约与运行验证前，不标记为语义已等价）：

1. **并发与阻塞边界**：Guest 侧 [GuestAPI.swift](../../../vphone-cli-up/VPhoneDaemon/Daemon/GuestAPI.swift) 的 `GuestAPI.queue` 为 `.concurrent`，但需实测验证长耗时命令经过宿主 `rpcAfterQueuedInput` 时是否阻塞同 VM 的其他并发请求（如健康探针、`screenshot`、`app_list`）。
2. **超时与断连后的子进程清理**：对照 [GuestShellSessionHandler.swift](../../../vphone-cli-up/VPhoneDaemon/Daemon/GuestShellSessionHandler.swift) 的 `GuestSessionLimit`，验证客户端超时或 UDS 断连后，命令进程及其子进程组是否被可靠终止并回收。
3. **消息大小上限（1 MiB）**：U 在宿主 [VPhoneHostAutomationServer.swift](../../../vphone-cli-up/VPhoneExecutable/VPhoneVirtualization/UI/VPhoneHostAutomationServer.swift)（`maximumRequestLength = 1 << 20`）与 Guest [GuestHyperTextHandler.swift](../../../vphone-cli-up/VPhoneDaemon/Daemon/GuestHyperTextHandler.swift)（`maximumJSONBody = 1 << 20`）均限制 JSON 报文不超过 **1 MiB**（L 旧上限为单流 1 MiB、宿主帧 2 MiB）。stdout/stderr 的单流截断阈值必须收紧（如各 ≤ 384 KiB），确保 JSON 编码后不触发 1 MiB 越界断连。
4. **运行身份父进程关系（`$PPID`）**：验证派生命令的 `$PPID` 是否仍对应 `vphoned` 以满足 [runtime_observation.py](../../../autophone/autophone/device/runtime_observation.py)，或同步更新身份观测契约。
5. **退出码、截断标志与取消语义**：验证 `exit_code`、`timed_out`、`stdout_truncated`、`stderr_truncated` 与 [shell.py](../../../autophone/autophone/device/shell.py) 契约一致。
