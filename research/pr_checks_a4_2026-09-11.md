## 快速检查

`.github/workflows/checks.yml` 在 push、pull_request 和手动触发时运行，使用 `macos-26` ARM64。该标签的架构见 [GitHub runner 文档](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。只初始化 Swift vendor 子模块，不下载固件、CFW 资源或创建 VM。

明确安装 Python 3.13、Keystone、zstd、xz 和 actionlint，调用既有 `make setup_venv` 与 A1 的 `make test`。在干净 checkout 中生成测试编译所需的 `VPhoneBuildInfo.swift`，无需运行签名构建。脚本检查使用 Python AST 和 bash/zsh 的 `-n`，只验证语法，不执行脚本；这不等同于完整语义静态分析。

pip 缓存随 Python 版本及 requirements/setup 脚本变化。Swift 缓存键包含操作系统、架构、Xcode/Swift/Python/原生依赖版本、子模块提交、Package 输入和当前提交；仅在相同工具链及依赖身份内复用先前构建。requirements 尚未锁定完整依赖版本，D2 仍未完成。

失败日志经 `tee` 保存，`pipefail` 保留失败退出状态。无 `continue-on-error`；摘要和日志上传使用 `always()`，日志保留 7 天。仓库只读权限，checkout 不保留凭据。

## 固件检查隔离

`.github/workflows/firmware-checks.yml` 是独立手动入口，仅允许 main，且要求仓库变量 `ENABLE_FIRMWARE_CI=true`。需另行配置 `vphone-firmware` 标签的 macOS ARM64 专用运行器、`firmware-validation` 环境（建议要求审批）、Swift 工具链及 `VPHONE_TEST_FIXTURES` 的完整只读样本路径。此工作没有注册运行器、设置仓库变量或触发该任务。

手动任务只调用 A1 `make test_firmware`，预检缺失或空文件会失败；不启动 VM，也不执行完整 less 验收。私有 VM 的启动和端到端验收尚无自动任务，不因增加此入口而标记完成。

`run_tests.py` 在启动 Swift 测试前清除继承的 `VPHONE_TEST_*`、`VPHONE_LESS_*`、`VPHONE_C4_*` 选择变量；固件模式只重新设置显式的 fixture 路径。这样快速检查不会因个人终端遗留的验收变量而处理真实固件。测试内部启动崩溃子进程所需变量仍由测试自身传入。
