## 4. 与设计的偏差

| 编号 | 位置 | 设计 | 实现 | 原因 |
| --- | --- | --- | --- | --- |
| G1 | `vm create` 参数 | 5.3 列出 `[--force-dsc-maxslide]` | 不传 | 本地 `vm create` 无该选项（第 2 节） |
| G2 | 后端选项 | 5.3：B4 不提供 native 后端 | Advanced 提供 Preparation、Restore 两项；“Default” 不传参数；`native` 标为 experimental；native 准备要求两个来源都是绝对路径，否则不构造命令 | 任务说明：只在高级选项中显式提供，默认值不变 |
| G3 | 进度读取 | 子进程存活期间每秒 `load` | 同左；另外创建视图打开且无自启运行时每 2 秒 `load` 一次（显示本会话未创建的机器的检查点）；Inspector 仍为 B2 的 5 秒 | 两者都只读文件、不取锁 |
| G4 | 取消 | 向分离会话的进程组发 SIGINT | `killpg(pid, SIGINT)`，只在组长未被回收时发送（此时组 ID 不会指向其他进程）；组长回收后不再发送，即使组内仍有成员 | 避免信号到达重用的进程组 ID |
| G5 | 创建日志 | 5.4：`-create` 后缀 | 新建创建替换该日志；续跑在日志末尾追加一行 `=== <时间> <命令> ===` 后追加输出（`ChildProcess.appendingToLog`） | 续跑不覆盖之前失败的输出 |
| G6 | 续跑参数 | `--resume`、`--restart-from`、`--accept-tool-change` | 另带 `--root-popup`（每次）与可选 `--keep-artifacts` | `--root-popup` 只在 CFW 未完成时由 CLI 使用；`--keep-artifacts` 为操作选项，不写入检查点 |
| G7 | 工具变化确认 | 列出检查点记录与当前可执行文件摘要 | 从 CLI `Error:` 行解析两个摘要并在确认框列出；检查点文件当前记录与 CLI 所报不同时另列一行；Launchpad 不自行计算摘要 | CLI 计算的是实际执行的内嵌可执行文件 |
| G8 | 退出确认 | 沿用上游提示，确认后取消 | `NSAlert` 列出机器名；Quit 后对每个自启创建运行的进程组发 SIGINT，然后立即退出，不等待子进程结束 | 上游创建流程在 app 内，退出即结束；本地创建在独立会话中，不取消会继续运行 |
| G9 | 启停与编辑 | — | 自启创建运行期间该机器 Start、Stop、编辑均不可用；状态显示 “Creating…” | 创建内部的 DFU 与首启属于 `vm create`；停止应走 Stop Creating |

## 5. 实现要点（事实）

### 5.1 命令

| 命令 | 参数 |
| --- | --- |
| 固件目录 | `fw catalog --json`（不记入命令历史，上游相同） |
| 新建 | `vm create <name> --library-root <root> --variant <regular\|dev\|jb\|exp> --iphone-source <s> --cloudos-source <s> --disk-size <GB> --root-popup [--keep-artifacts] [--frida] [--spoof-build <id>，仅 exp] [--prepare-backend <b>] [--restore-backend <b>]` |
| 续跑 | `vm create <name> --resume --library-root <root> --root-popup [--restart-from <stage>] [--accept-tool-change] [--keep-artifacts]` |
| 状态 | `vm create-status <name> --json --library-root <root>`，只在自启创建运行退出后运行一次 |

- 任何命令都不含 `--sudo-password`、`--interactive`、`--dfu`；create 与 resume 各含一次 `--root-popup`；Launchpad 不处理密码。
- less：`VPhoneLaunchpadCreateVariant.less.isAvailable == false`；`create` 与 `resume` 工厂对 less 返回 nil。New Machine 的变体菜单中 less 项禁用，选择 less 时页脚显示原因；less 检查点的创建视图不提供 Resume，显示同一原因。
- 新建与续跑经 `VPhoneLaunchpadCommandLine.start(_:logFile:appendingToLog:onLine:)` 分离启动（B2 的 setsid、disclaim、SIGDEF、stdin `/dev/null`），输出写入 `<logs>/<name>[-<digest8>]-create.log`，记入命令历史。

### 5.2 进度与状态

- 自启运行存活期间，每秒在主 actor 外调用 `VPhoneCreateCheckpointStore.load(bundleURL:)`；退出后再读一次，然后运行一次 `create-status --json`。
- `VPhoneLaunchpadMachineLibrary.refresh()`（5 秒周期）未改动：只运行 `vm list --json` 与 `ps`，不读检查点，不运行 `create-status`。
- 状态文字保留检查点拼写。图标映射：`succeeded` 绿；`unverified`、`cancelled`、`completed_unverified`、`interrupted` 琥珀；`failed`、`recovery_required` 红；`pending`、`not_applicable`、`incomplete` 次要色；自启运行存活时总状态显示 `running`、运行中阶段显示蓝色转圈，运行结束后同一阶段显示琥珀。
- 阶段行显示 `reason`（`unverified`、`not_applicable` 的原因）或 `error`，以及开始到结束的时长。`recovery_required` 另列 kind、stage、detail、action。
- 运行结束后显示退出状态、失败时输出末尾 20 行、`create-status` 的 `live.create_run_in_progress`、`live.bundle_lock_held`、`live.firmware_transaction`。

### 5.3 续跑与工具变化

- `canResume`：工具链已校验、机器 `canStart`（无动作、无导出、无自启创建运行、`ps` 判定停止）、检查点可读、变体不是 less。
- Resume 选项：“Next unfinished stage (<stage>)” 或 “Restart from <stage>”（`restartableStages`：不晚于下一个未完成阶段；全部完成时为全部阶段）；可选保留恢复文件。
- 续跑非 0 退出且输出含工具变化 `Error:` 行时，设置 `toolChange` 并弹出确认；“Resume with This Build” 以同一 `--restart-from` 与 `--keep-artifacts` 加 `--accept-tool-change` 再运行；Cancel 清除该状态，不运行命令。

### 5.4 取消与退出

- Stop Creating 先弹确认，确认后 `VPhoneLaunchpadCreation.cancel()` → `interruptGroup()` → `killpg(detachedPID, SIGINT)`。
- `applicationShouldTerminate`：`VPhoneLaunchpadQuit.decision` 为 `.confirm(machines:)` 时弹 `NSAlert`；Quit 调用 `VPhoneLaunchpadQuit.confirmed`（对每个自启运行的进程组发 SIGINT）后返回 `.terminateNow`；Cancel 返回 `.terminateCancel`。

### 5.5 字符串

## 8. 事实、推断与未覆盖

事实：

- Launchpad 构造的创建命令只有四种形状；不含密码与交互参数；非 less 含 `--root-popup`；less 不构造。源码扫描与单元测试同时检查。
- 周期刷新不运行 `create-status`、不读检查点；`create-status` 只在自启运行退出后运行一次（源码扫描与替身计数）。
- 替身进程组（3 个进程，均为前台、无 SIGINT 处理）在 `killpg` 后全部结束；只向组长发 SIGINT 时组长不结束（负对照）。
- 内嵌 CLI 的 `vm create --help` 列出工厂使用的全部 14 个选项；`create-status --json` 输出可被 Kit 解码，总状态与 Kit 从同一检查点算出的一致。

推断：

- 真实 `vm create` 收到进程组 SIGINT 后按默认处置结束。依据：`VPhoneCreate*.swift` 无 SIGINT 处理（设计 5.3 与第 2 节）。未在真实运行中验证。
- 真实子进程（`fw_prepare.sh`、下载工具、Python restore、DFU `vphone-vm`、osascript）留在 `vm create` 的进程组内。依据：`VPhoneProcessRunner` 中未发现 `setpgid`/`setsid`；交互 sudo 路径的 `tcsetpgrp` 在 Launchpad 场景不触发（stdin 为 `/dev/null`，使用 `--root-popup`）。是否每个子进程都随 SIGINT 结束，未验证。
- `vphone-vm` 子进程收到 SIGINT 后的行为以其自身处理为准（B2 推断其将 SIGINT 作为停止）；取消发生在 restore 中途时设备与 bundle 锁的状态未验证。

## 10. 真实创建验收步骤建议（需用户授权）

前提：

1. amfidont 已按 `make amfidont_allow_vphone` 放行；`make build` 后重新 `make launchpad` 与 `make check_launchpad`。
2. 选一个专用库根，例如 `~/vphone-b4-accept`（不是 `~/.vphone/VMs`），所在 APFS 宗卷可用空间不少于约 90 GB；网络可下载 IPSW，或准备本地 IPSW（Custom IPSWs）。
3. 其他 VM 不运行；记录 `ps -axo pid,ppid,pgid,stat,command` 基线。

步骤：

1. `open .build/vphone-launchpad.app`；New Machine… → 名称 `lp-b4-accept`，Location 选 Other… 指向专用库根，Catalog 选一组配对（或 Custom IPSWs），变体 regular，磁盘 64 GB。用 (i) 记录命令，确认不含 `--sudo-password`、含 `--root-popup`。Create。
2. 创建视图：记录各阶段状态变化与检查点 `updated_at` 的时间差；`ps` 中 `vm create` 的 pgid 等于其 PID、`stat` 含 `s`；`~/Library/Logs/vphone-cli-launchpad/lp-b4-accept-<digest8>-create.log` 增长。
3. 取消（prepare 阶段，下载或 `fw_prepare.sh` 运行中）：Stop Creating… → 确认。记录 `ps -g <pgid>` 变为空所需时间与任何残留进程；总状态 `interrupted`；Result 节 `Run lock held false`、`Bundle lock held false`。
4. 续跑：Resume… → Next unfinished stage → Resume。CFW 阶段出现 macOS 认证对话框，由用户在系统对话框输入密码；确认 Launchpad 日志与命令历史中无密码。
5. 取消（restore 阶段，DFU `vphone-vm` 运行中）：同步骤 3，另记录 DFU `vphone-vm` 是否退出、`create-status` 的 `firmware_transaction`；随后 Resume。
6. 退出确认：某阶段运行中按 ⌘Q → 确认框列出 `lp-b4-accept` → Quit；记录进程组是否全部结束；重新打开 Launchpad，选中机器 → Show Creation…，检查点为 `interrupted`；Resume。
7. 工具变化：在一次中断后执行 `make build && make launchpad`，重新打开 Launchpad 并 Resume；应出现 “The vphone-cli toolchain changed” 确认框，列出两个摘要；Cancel 不运行命令；“Resume with This Build” 的命令含 `--accept-tool-change`。
8. 完成：总状态 `succeeded` 或 `completed_unverified`（后者列出 `unverified` 阶段与原因）；随后用 B2 的 Start/Stop 启停一次。
9. 记录：每次取消到进程组结束的时间与残留进程、各阶段耗时、日志路径、最终检查点；验收后由用户决定是否删除 `lp-b4-accept`。
